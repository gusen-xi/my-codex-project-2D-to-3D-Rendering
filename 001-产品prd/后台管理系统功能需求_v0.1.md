# 后台管理系统功能需求 v0.1

## 1. 文档信息

- 产品：平面图生成室内效果图
- 文档类型：后台管理系统功能需求
- 版本：v0.1（MVP 范围）
- 状态：范围已确认，待实现评审
- 数据库约束：仅允许为超级管理员身份授权新增 **一张** `super_admins` 表；不得修改任何现有表结构，不得新增第二张表或其他数据库对象。其余后台能力只使用现有 MySQL 表和字段。

## 2. 背景与目标

当前产品面向住宅室内设计师、软装设计师和小型设计工作室，支持上传户型图、核对房间结构、生成室内意向图及局部修改。后台定位为作品集 MVP，以本地演示为主，用于展示管理员查看注册用户、产品使用情况、生成任务状态及人工质量评价的能力。

首版遵循**现有 schema 只读、仅新增一张超级管理员授权表、最小权限**原则，以只读查询和演示观察为主，不提供用户数据编辑、封禁、删除、模型参数配置或明细数据导出。默认不展示、传输或导出住宅图纸及生成图文件内容，优先保障用户隐私图纸安全。

## 3. 用户与权限

### 3.1 使用者

- 超级管理员：使用现有账号密码登录；仅当账号已登记在 `super_admins` 表中时，才可查看完成演示所需的最少管理数据并进行筛选。
- 普通设计师：继续使用现有创作产品，不得访问管理页面或管理接口。

### 3.2 访问控制要求

- 管理页面和每个管理 API 都必须由服务端鉴权，不能只依靠前端隐藏菜单。
- 当前 `users` 表和 `auth_sessions` 表没有管理员角色字段或权限级别。沿用现有账号密码登录及 `auth_sessions` 会话；服务端通过当前会话对应的 `user_id` 查询 `super_admins`，仅匹配的账号获得后台权限。不得仅凭前端标记、用户名或环境变量直接放行。
- `super_admins` 仅登记一个超级管理员用户 ID；应用启动或管理接口应拒绝零条或多条有效超级管理员记录，避免权限边界不明确。
- 未登录访问管理页面应进入登录流程；普通用户访问管理 API 返回拒绝响应，且不返回管理数据。
- 管理后台使用与产品相同的登录身份；不得在浏览器端保存管理员密码或扩大现有会话有效期。

## 4. 首版范围

### 4.1 管理概览

展示按现有数据可计算的基础指标，并注明统计口径和更新时间：

- 注册用户总数、近期新增用户数（来源：`users.created_at`）。
- 项目数、样例项目数、非样例项目数（来源：`projects.is_sample`）。
- 任务总数、处理中、成功、失败及结果未知的任务数（来源：`model_tasks.status`）。
- 生成、局部编辑、全图换风格和识别任务数量（来源：`model_tasks.action`）。
- 已保存渲染版本数、人工评价数及评价字段的通过/未通过/未评价分布（来源：`render_versions`、`version_reviews`）。
- 任务耗时仅对存在开始和结束时间的记录计算；费用仅汇总已记录且币种一致的 `actual_cost`。未知费用显示“未记录”，不按 0 计。

首版不承诺实时监控。页面打开或用户手动刷新时查询；具体刷新策略按试用规模确定。

### 4.2 用户管理

- 用户列表：用户名、用户 ID、注册时间、项目数、任务数、最近项目更新时间（若可由现有数据关联计算）。
- 支持按用户名精确或模糊查询，按注册时间排序和分页。
- 用户详情：基础账号信息、项目数量和项目列表摘要、任务数量及任务状态汇总。
- 密码派生信息、盐值、会话令牌、头像文件路径和其他认证材料不得展示或导出。
- 不提供查看或重置密码、注销会话、封禁、删除、改名等操作。

### 4.3 项目管理

- 项目列表：项目名称、所属用户名、是否样例、创建时间、更新时间、关联素材数、任务数、已生成版本数。默认不展示面积和用户上传的原始文件名，减少不必要的住宅项目信息暴露。
- 支持按所属用户、项目名称、样例/非样例、时间范围筛选；按更新时间排序和分页。
- 项目详情以只读方式展示项目基础信息、房间数量、任务及版本摘要。
- `workspace_draft` 是工作台恢复草稿，不作为历史事实来源；后台默认不展示草稿 JSON。
- 样例项目单独标识，统计用户使用情况时应能够排除样例数据，避免误计为普通用户行为。

### 4.4 生成任务与质量观察

- 任务列表：任务 ID、所属用户、项目、动作类型、状态、提交/开始/结束时间、耗时、模型提供商与模型名称、是否记录费用、错误摘要。
- 支持按状态、动作、用户、项目和时间范围筛选；支持查看单条任务的非敏感请求摘要和结果摘要。
- 请求/结果快照仅展示用于排查的必要字段；隐藏凭据、完整本地路径、访问令牌及第三方响应中的敏感信息。
- 对失败和 `unknown` 状态分别展示；`unknown` 表示上游结果可能未确认，不能直接归为失败或自动重试。
- 质量观察页展示人工评价：结构保持、布局保持、可用于客户沟通、局部编辑区域保持及备注；NULL 显示“未评价”，不能当作不通过。
- 可以从任务查看关联渲染版本元信息；MVP 不提供图纸或生成效果图预览、原文件访问、下载或打包，避免扩大隐私图纸的暴露面。

### 4.5 查询与导出

- 首版不提供用户、项目、任务明细 CSV 导出、批量下载或图纸打包能力；页面内筛选和分页仅用于只读查看。
- 后续如需导出，须单独评审字段白名单、范围上限、落盘位置、清理方式及访问留痕；本需求不包含该能力。当前数据库没有管理审计表，不能声称已有持久审计能力。

### 4.6 系统状态（轻量）

- 展示现有 `/health` 检查可确认的服务和 MySQL 连通状态，以及现有 `/api/config` 提供的生图配置就绪状态。
- 对外展示健康状态和最近一次检查时间，不展示环境变量、密钥、连接串或内部诊断原文。
- 本地演示只保留排查运行问题所需的最少本地事件信息；不得记录图纸/效果图内容、完整文件路径、密码、会话令牌、密钥或完整请求快照。日志不写入数据库，启动说明应明确本地日志位置和清理方式。
- 首版不建设告警规则、队列监控、用量计费面板或模型服务商管理。

## 5. 页面结构建议

1. **管理概览**：关键指标卡片、近期任务状态分布、人工评价概况、服务就绪状态。
2. **用户管理**：用户列表、筛选、用户只读详情。
3. **项目管理**：项目列表、样例标识、项目只读详情。
4. **生成任务**：任务筛选列表、任务摘要、关联版本和评价查看。
5. **质量评价**：评价分布与评价明细，不显示关联住宅图纸或生成图内容。

导航入口仅对已识别为管理员的账号显示；隐藏入口只改善体验，不替代服务端授权。

## 6. 数据来源与限制

| 管理数据 | 当前来源 | 可支持的内容 | 限制 |
|---|---|---|---|
| 用户与注册时间 | `users` | 用户列表、注册趋势 | 无角色、状态、禁用时间、最后登录时间字段 |
| 登录会话 | `auth_sessions` | 复用现有登录会话识别当前用户 | 无设备/IP/管理员操作记录；后台不得暴露令牌摘要 |
| 超级管理员授权 | 新增 `super_admins` | 通过现有 `users.id` 授权一个超级管理员账号 | 本需求唯一允许新增的表；不存储密码、会话令牌或用户图纸信息 |
| 项目 | `projects` | 用户归属、样例标志、面积、时间 | 无独立项目状态或删除记录 |
| 文件素材元信息 | `assets` | 素材类型及必要的关联计数 | 不展示原始文件名、存储路径或图纸尺寸；文件本体不经管理后台读取 |
| 房间核对 | `rooms` | 房间范围、尺寸描述、确认人和时间 | 当前值不一定等于历史任务时的值，应以任务快照为准 |
| 模型任务 | `model_tasks` | 动作、状态、时间、提供商、错误摘要、费用字段 | 部分任务可能处于内存执行状态，数据完整性以数据库实际记录为准；费用未知为 NULL |
| 渲染版本 | `render_versions` | 成功版本、风格、来源和父版本 | 版本图片仍需通过受权限保护的文件接口访问 |
| 人工评价 | `version_reviews` | 结构、布局、可用性和编辑区域评价 | NULL 代表未评价；缺少评价不代表质量通过或失败 |

所有列表、统计和详情均须遵守用户与项目关联关系。后台管理员的跨用户查看权限必须由后端显式授权；普通用户接口原有的数据隔离规则不能被绕开或削弱。

## 7. 非目标与明确禁止事项

- 不修改任何现有数据库表、字段、索引或约束；仅允许新增本需求定义的 `super_admins` 一张表及其必要主键/外键约束，不得新增其他表或数据库对象。
- 不执行与 `super_admins` 无关的建表、迁移或生产数据修复脚本。
- 首版不编辑或删除用户、项目、素材、任务、版本和评价。
- 不封禁用户、重置密码或撤销会话；当前 schema 没有对应状态字段和管理审计机制。
- 不提供图纸/生成图预览、跨用户下载原始图纸、生成大图批量打包或查看所有本地文件的入口。
- 不提供 CSV 明细导出；不建立超出本地演示排障需要的日志采集。
- 不将当前数据结构缺失的登录 IP、最后活跃时间、管理员操作日志、精确 token 用量、成本明细等伪装成现有指标。
- 不建设团队/租户权限、收费账单、套餐、客服工单、消息通知和复杂角色管理。

## 8. 验收标准

1. 只有已登录且其 `user_id` 存在于 `super_admins` 的唯一超级管理员可获取管理 API 数据；普通登录用户和未登录用户均无法访问。
2. 管理概览指标可追溯到本文件列明的现有表和字段，统计口径清晰；未知成本和未评价值按规则展示。
3. 用户、项目和任务列表支持对应筛选、分页、排序；详情只读且不暴露认证敏感信息。
4. 样例项目可与普通用户项目区分，统计可排除样例项目。
5. 查看任务时能够区分 queued/running/completed/failed/unknown，且不会把 unknown 当作失败自动重试。
6. MVP 不开放管理后台文件读取接口；任何图纸文件都不能通过猜测 URL 或传入文件路径从后台访问。
7. 后台不能预览、下载或导出住宅图纸与生成图；不能通过猜测 URL 或传入文件路径读取用户文件。
8. 日志不包含图纸内容、完整路径、密码、会话令牌、密钥或完整请求快照，并能按本地说明清理。
9. MVP 不提供明细 CSV 导出；数据库只新增 `super_admins` 一张授权表，其他表结构与现有数据库对象保持不变。

## 9. 已确认决策与实现前检查

- 产品定位：作品集 MVP，以本地演示为主；当前需求不包含公网部署。
- 数据边界：`users`、`auth_sessions` 及所有业务表只读、不改结构；唯一允许新增 `super_admins` 授权表，除此之外不增加其他表或数据库对象。后台管理接口只授予唯一超级管理员完成演示所需的最小只读权限。
- 登录边界：超级管理员使用现有账号密码登录和会话；授权通过 `super_admins.user_id` 与现有 `users.id` 关联，不在新表重复保存凭据或会话。
- 隐私边界：后台不展示、传输、预览、下载或导出住宅图纸与生成图；只显示必要的记录元数据和汇总信息。
- 导出边界：MVP 不提供明细 CSV、批量下载或图纸打包。
- 日志边界：仅保留本地演示排障所需的最少信息；不得记录图纸内容、完整路径、密码、会话令牌、密钥或完整请求快照；日志位置与清理方法应写入本地启动说明。数据库不新增审计表。
- 超级管理员初始化：先在现有 `users` 表中准备其普通账号，再通过受控的一次性初始化操作将该用户 ID 登记到 `super_admins`；不得在前端硬编码身份或权限。初始化和恢复流程需避免产生多个有效超级管理员。
- 成本指标：仅在已有字段存在有效记录时展示，并明确标注覆盖范围；不作为 MVP 验收门槛，不推算缺失费用。
- 后续若计划开放文件预览、导出、账号管理或公网访问，须另行评审隐私与权限方案；不能视为本版已授权。

## 10. 数据库兼容说明

本需求以现有表的只读管理为主。当前 schema 包含 `users`、`auth_sessions`、`projects`、`assets`、`rooms`、`model_tasks`、`render_versions` 和 `version_reviews`。唯一授权的 schema 变更是新增一张 `super_admins` 表，结构限定如下：

| 字段 | 类型建议 | 约束与用途 |
|---|---|---|
| `singleton_id` | `TINYINT UNSIGNED` | 主键，固定为 `1` 并由 CHECK 约束限制为 `1`，保证该表最多只有一条授权记录 |
| `user_id` | `BIGINT UNSIGNED` | 非空且唯一，外键引用 `users.id`；仅登记被授权的超级管理员账号 |
| `created_at` | `DATETIME(3)` | 非空，默认当前时间；记录授权登记时间 |

该表不得加入密码、密码盐、会话令牌、住宅图纸路径或业务数据；不新增角色字段、审计表、视图、触发器或其他表。登录凭据和会话继续使用现有 `users` 与 `auth_sessions`。应用初始化时必须确认授权记录恰好一条；该表主键约束保证最多一条，初始化流程负责保证至少一条。除新增此表及一条受控的超级管理员授权记录外，不修改现有数据库结构；本后台不对现有业务数据执行写操作。
