# 平面图生成室内效果图 PRD

版本：v0.1  
状态：需求草案，待评审与原型验证  
更新时间：2026-11-16  
产品形态：供产品发起人与少量设计师试用的网页原型  
负责人：待指定

采用标准 PRD：本产品涉及结构识别、生成和连续编辑，需明确各环节的约束、失败处理与验收方式。

## 1. 背景与问题

住宅室内设计师、软装设计师和小型设计工作室，在初次客户沟通时，需要根据户型平面图快速展示装修风格意向。

当前依赖手动建模渲染或外包效果图，耗时、成本和修改等待影响沟通效率。核心问题是：**从客户平面图到一张能讨论风格的图片，过程过长，且客户反馈后难以快速修改。**

本产品帮助设计师在保留空间结构和布局的前提下，生成单房间室内透视图，并通过局部重绘继续调整方案。

## 2. 目标、成功标准与非目标

### 2.1 产品目标

- 缩短平面图到风格初稿的过程，减少前期手动建模工作。
- 让设计师通过一次轻量核对，确认生成所依据的空间信息。
- 支持根据客户反馈修改局部，延续已有方案。

### 2.2 成功标准

| 验证维度 | 可观察信号 | 判定方式 |
|---|---|---|
| 完整流程 | 试用者能完成上传、确认、生成和局部修改 | 记录任务完成情况、人工协助与中断原因 |
| 沟通价值 | 设计师认为图片可用于与客户讨论风格 | 逐张评价并说明可用或不可用原因 |
| 结构保持 | 图片符合已确认的墙体、门窗、空间分隔和固定家具位置 | 对照平面图、确认记录与生成结果检查 |
| 编辑保持 | 局部修改未改变视角、结构和其他区域 | 对照修改前后图片检查 |
| 效率 | 相比试用者现有流程，获得可用初稿更快 | 记录现有流程基线、生成耗时及总操作耗时 |
| 成本 | 能统计获得一张可用图的实际成本 | 纳入失败、重试与编辑消耗 |

**目标是几分钟内获得初稿，具体时间门槛、通过率和成本上限待实验确定，不作为现阶段承诺。**

### 2.3 超出首版范围

- 三维鸟瞰图、同一空间多视角和全屋连续生成。
- 完整三维建模、施工图输出及施工精度保证。
- 原生 CAD 文件解析；首版以 CAD 导出图片作为输入。
- 收费、订阅、支付和商业定价。
- 多人协作及复杂工作室管理功能。

## 3. 用户与使用场景

**主用户：**住宅室内设计师、软装设计师、小型设计工作室的方案设计人员。

**核心场景：**设计师获得客户户型图后，选择一个房间，补充风格与参考信息，生成意向图；根据客户反馈调整沙发、材质、软装或灯光，继续讨论方案。

客户是图片的沟通对象，首版不要求客户直接操作产品。

## 4. 首版范围与优先级

Must 为验证核心链路必需；Should 改善体验，可在核心能力跑通后补充；Could 视试用结果决定。

| 优先级 | 需求 | 范围及理由 |
|---|---|---|
| Must | 上传平面图 | 支持 JPG、PNG、PDF；多页 PDF 可选择目标页 |
| Must | 选择目标房间 | 从整套户型中明确本次生成范围 |
| Must | 自动识别与一次核对 | 识别墙体、门窗、房间边界、固定家具和可读尺寸，允许纠正 |
| Must | 自动推荐视角 | 默认提供观察位置和朝向，允许微调 |
| Must | 设置风格并生成 | 生成单房间室内透视图 |
| Must | 局部重绘 | 框选区域并描述修改要求，支持继续修改 |
| Must | 全图风格修改 | 变更材质、家具款式、软装和氛围，锁定结构及布局 |
| Must | 保留编辑版本 | 修改失败或不满意时，能返回此前结果 |
| Must | 查看与下载图片 | 支持实际用于客户沟通 |
| Must | 状态与失败恢复 | 展示处理状态，失败后保留输入和已确认内容 |
| Should | 风格参考图 | 辅助表达材质、配色和氛围，不改变结构约束 |
| Should | 修改前后对比 | 帮助核对变化与选择版本 |
| Could | 常用风格快捷选项 | 减少重复输入，具体内容由试用反馈决定 |

手绘草图和信息不完整的 CAD 导出图进入试验样本；不预先承诺与清晰、带尺寸平面图同等的识别表现。

## 5. 主流程

1. **上传平面图**  
   设计师上传图片或 PDF，并选择目标页面。

2. **选择房间**  
   系统提供房间选择结果，设计师可纠正目标范围。

3. **核对结构**  
   系统集中展示识别出的门窗、固定家具、尺寸等信息。设计师一次核对并按需纠正；不确定的信息应明确标出。

4. **确认默认视角**  
   系统推荐观察位置与朝向，设计师可直接采用或微调。

5. **设置设计意向**  
   选择或描述风格，可补充层高、材质偏好和参考图。

6. **生成与查看**  
   展示任务状态，完成后查看图片；失败时保留已有配置并允许重试。

7. **继续修改**  
   框选局部提出修改，或调整全图风格。每次成功结果形成可返回的版本。

8. **下载结果**  
   下载选定版本，用于客户风格沟通。

## 6. 产品规则

### 6.1 空间与布局约束

生成和编辑均以**设计师核对后的结构信息**为依据，保留：

- 墙体位置、房间分隔和空间比例。
- 门窗洞口的位置。
- 固定家具的位置。
- 主要家具的布局、占用范围与尺寸比例。

允许变化：材质、颜色、家具款式、软装及灯光氛围。

替换家具款式时，应保持其布局与占用范围。固定家具的外观可调整，但位置不可移动。

### 6.2 识别与确认

- 尺寸无法读取时，应标记为缺失或不确定，不将推测值展示为已识别事实。
- 设计师可纠正关键结构与尺寸信息；后续生成应采用纠正结果。
- 存在影响生成的结构缺失或冲突时，应说明需补充什么，避免反复上传。
- 不要求设计师完成建模；具体核对界面和操作数量需通过原型验证。

### 6.3 视角

- 系统默认提供一个推荐视角，减少主动设置步骤。
- 设计师可以调整观察位置和朝向。
- 推荐视角应位于可用空间内，避免明显穿墙或被固定物遮挡。
- 局部重绘及全图风格修改沿用原视角。主动更换视角视为重新生成，首版不承诺多视角一致性。

### 6.4 局部修改

- 用户框选区域并描述更换要求。
- 保持视角、空间结构、其他家具及未选区域一致。
- 仅允许因替换产生必要的阴影和光照变化。
- 框选过大、修改对象不清或要求涉及结构变化时，应提示调整范围或说明冲突。
- 生成新版本前保留原图，支持基于选定版本继续修改。

### 6.5 全图风格修改

全图风格修改可以改变材质、配色、家具款式、软装和灯光氛围，但仍须保留原视角、结构、门窗和布局。

涉及移墙、移门窗或移动固定家具的要求，应提示超出首版修改范围。

## 7. 用户故事与验收标准

| 编号 | 用户故事 | 验收标准 |
|---|---|---|
| A01 | 设计师上传户型资料 | JPG、PNG 或可解析 PDF 能进入房间选择；不可用文件显示原因及处理建议 |
| A02 | 设计师核对自动识别结果 | 可看到目标房间及关键结构；纠正结果被保存并用于后续生成 |
| A03 | 设计师处理信息缺失 | 无法读取的尺寸明确标记；影响生成的缺失项提示补充，不静默编造 |
| A04 | 设计师使用默认视角 | 无须手动设置即可继续；调整后生成采用所选位置与朝向 |
| A05 | 设计师生成风格初稿 | 结果为目标房间透视图，符合风格输入，并通过结构与布局对照检查 |
| A06 | 设计师替换沙发 | 沙发外观按要求变化；视角、结构、其他家具及未选区域保持一致，仅允许必要阴影变化 |
| A07 | 设计师切换整屋风格 | 风格发生变化；结构、门窗、固定家具位置和主要布局保持一致 |
| A08 | 设计师连续修改 | 可基于选定结果再次编辑，并返回此前成功版本 |
| A09 | 任务失败后恢复 | 显示失败状态并允许重试；上传资料、核对结果及编辑要求不丢失 |
| A10 | 设计师下载结果 | 下载内容与选定版本一致，文件可正常打开 |

**验收注意：**透视图只展示部分空间。当前视角看不到的墙体或门窗，不应因“未出现”判为错误，也不能据此认定整个房间结构已验证。

## 8. 原型验证与数据记录

Demo 阶段将以用户提供的一个真实住宅项目作为测试样例，以该项目的平面方案图为输入，对照同项目的人工效果图，评估生成结果的空间结构、布局与风格表达。CAD 工程文件将在后续正式提供，Demo 阶段先基于平面图开展验证。

建议使用少量真实、已获使用授权的户型样本，覆盖清晰平面图、尺寸不全、图面复杂及手绘草图等情况，并分别记录结果。

每次试用至少记录：

- 输入类型、清晰度和缺失信息。
- 自动识别错误、人工纠正内容及操作耗时。
- 首次生成耗时、重试次数和实际成本。
- 结构与布局错误的具体类型。
- 初稿能否用于客户沟通，以及原因。
- 局部修改是否成功、是否影响其他区域。
- 获得最终可用图的总耗时与总成本。

结构保持和编辑保持属于核心验证项。若持续无法满足，应回到输入确认、生成方案或首版适用范围调整，不能只通过优化图片观感宣布验证成功。

## 9. 非功能与资料要求

- **状态可见：**上传、识别、生成、编辑及失败状态应可区分。
- **防止重复任务：**提交后应明确反馈任务已受理，避免重复点击产生多个任务。
- **恢复能力：**生成或编辑失败不覆盖已有成功结果。
- **资料使用：**试用前明确平面图、参考图和结果的存储位置、访问范围与删除方式。
- **外部服务：**若使用第三方服务处理资料，应告知试用者资料去向。
- **性能与兼容：**支持的浏览器、文件大小、图片分辨率、超时规则和并发量待实验确定。

## 10. 验证阶段与主要风险

| 阶段 | 产出 | 进入下一阶段的依据 |
|---|---|---|
| 能力验证 | 真实样本的识别、生成及编辑结果 | 能说明结构保持和局部修改的适用条件、失败类型 |
| 网页原型 | 可完成的核心操作链路 | 用户能完成任务，失败可恢复，结果可追溯 |
| 小范围试用 | 用户反馈、质量、耗时与成本记录 | 据实际数据决定继续投入、缩小范围或调整方案 |

主要风险：

- **结构保持尚未验证：**能生成美观图片，不代表能遵循平面图。
- **输入信息不足：**平面图通常不完整表达高度、窗台、吊顶等信息；需区分用户补充与设计推断。
- **局部编辑影响外部区域：**多轮修改可能累积结构和画面偏差。
- **轻量确认与准确性存在取舍：**需验证一次核对是否足够，同时避免变成手动建模。
- **反复重试抵消效率收益：**应以获得可用结果的总耗时和总成本评价产品。

以下问题不改变已确认的产品方向，但会影响实现或验收。

| 问题 | 影响 | 建议负责人 |
|---|---|---|
| 首批试用者与授权样本如何取得？ | 决定验证能否启动及覆盖哪些户型 | 产品发起人 |
| 固定家具如何识别、标记和纠正？ | 决定结构核对的操作负担 | 产品、设计 |
| 尺寸缺失时，最低补充要求是什么？ | 决定哪些输入可进入生成 | 产品、技术 |
| 如何判定比例偏差、局部编辑越界及必要阴影变化？ | 决定可重复执行的验收标准 | 产品、试用设计师、技术 |
| 哪种生成方案能满足结构与编辑约束？ | 决定核心能力是否成立 | 技术 |
| 时间、成本、输出分辨率及文件限制是多少？ | 决定服务边界与后续投入 | 产品、技术，依据实验确认 |
| 试用资料如何存储、访问和删除？ | 决定真实客户资料的试用条件 | 产品发起人、技术 |

**当前可进入样本准备、交互设计和能力实验；结构保持与编辑保持的效果承诺，须在实验后确定。**
